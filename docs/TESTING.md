# Тестирование приложения «Белтелеком — магазин»

Одним из важнейших этапов тестирования программного обеспечения является создание тест-кейсов, которые позволяют систематически проверять корректность работы всех функций приложения. В рамках разработки интернет-магазина была составлена серия тест-кейсов, охватывающих ключевые сценарии взаимодействия пользователя с системой: вход и регистрация, оформление заказа, редактирование профиля и администрирование пользователей.

Для обеспечения корректной и стабильной работы программы было проведено всестороннее тестирование алгоритмов валидации и пользовательского интерфейса. Особое внимание уделялось проверке правильности ввода email, телефона и адреса доставки, а также обработке возможных ошибок на клиенте и на сервере API.

Логика проверки данных реализована в двух согласованных модулях:

- **клиент:** `public/js/core/validation.js` (`BeltelecomValidate`);
- **сервер:** `api/lib/validation.php` (функции `validate_user_email`, `validate_user_phone_optional`, `validate_user_address_format` и др.).

## Ручные тест-кейсы (примеры)

### Тест-кейс TC001 — Проверка корректности ввода email при входе

| Поле | Значение |
|------|----------|
| **Идентификатор** | TC001 |
| **Название** | Проверка функции валидации поля «Email» на странице входа |
| **Предусловия** | Пользователь открыл страницу `login.html`, активна вкладка «Вход», поле «Email» доступно для редактирования. |
| **Шаги выполнения** | 1. Открыть страницу входа.<br>2. Ввести в поле «Email» значение: `иван@mail.com` (кириллица в локальной части).<br>3. Ввести пароль и нажать «Войти». |
| **Ожидаемый результат** | Появляется сообщение об ошибке: «Email может содержать только латинские буквы, цифры, точку и символ @ (например: ivan.petrov@mail.com)»; запрос на сервер не отправляется. |
| **Фактический результат** | _Заполняется после проведения теста._ |
| **Примечания** | Аналогично можно проверить пустое поле, email без домена (`user@`), двойные точки (`user..name@mail.com`). |

### Тест-кейс TC002 — Проверка телефона при оформлении заказа

| Поле | Значение |
|------|----------|
| **Идентификатор** | TC002 |
| **Название** | Проверка валидации белорусского мобильного номера в корзине |
| **Предусловия** | В корзине есть хотя бы один товар; открыта страница `cart.html`, форма оформления заказа видна. |
| **Шаги выполнения** | 1. Заполнить поле «Имя» (не менее 2 символов).<br>2. Ввести в поле «Телефон» значение: `+375 20 123 45 67` (код оператора 20 не поддерживается).<br>3. Указать адрес в формате «Минск, Независимости, 10».<br>4. Нажать «Отправить заказ». |
| **Ожидаемый результат** | Сообщение: «Некорректный белорусский мобильный номер (коды 29, 33, 44, 25)»; заказ не создаётся. |
| **Фактический результат** | _Заполняется после проведения теста._ |
| **Примечания** | Дополнительно проверить пустой телефон, номер из 8 цифр, ввод букв в поле телефона. |

### Тест-кейс TC003 — Проверка адреса доставки

| Поле | Значение |
|------|----------|
| **Идентификатор** | TC003 |
| **Название** | Проверка формата адреса «Город, улица, дом» |
| **Предусловия** | Открыта страница `cart.html`, корзина не пуста. |
| **Шаги выполнения** | 1. Заполнить имя и корректный телефон `+375291234567`.<br>2. Ввести в поле «Адрес» значение: `Минск, проспект` (менее трёх частей, нет номера дома).<br>3. Нажать «Отправить заказ». |
| **Ожидаемый результат** | Сообщение: «Адрес указан некорректно. Укажите в формате: Город, улица, дом»; заказ не сохраняется. |
| **Фактический результат** | _Заполняется после проведения теста._ |
| **Примечания** | При вводе запрещённых символов (например, `#`) клиент автоматически удаляет их из поля. |

## Юнит-тестирование

Юнит-тестирование позволяет проверять корректность работы отдельных модулей программы — например, функций валидации — в изоляции от остальной системы. Это существенно упрощает выявление и устранение ошибок на ранних этапах разработки.

### Серверная валидация (PHP)

Модуль `api/lib/validation.php` содержит функции проверки email, телефона и адреса. Набор тестов расположен в `tests/php/UserValidationTest.php` и запускается командой:

```bash
php tests/php/UserValidationTest.php
```

### Клиентская валидация (JavaScript)

Модуль `public/js/core/validation.js` экспортирует объект `BeltelecomValidate` с методами `emailError`, `phoneError`, `addressError` и др. Тесты в `tests/js/validation.test.mjs` используют встроенный раннер Node.js:

```bash
node --test tests/js/validation.test.mjs
```

### Запуск всех тестов

```bash
npm test
```

## Описание юнит-тестов (PHP)

| Тест | Назначение |
|------|------------|
| `validate_user_email_Empty_ReturnsError` | Пустой email |
| `validate_user_email_InvalidCyrillic_ReturnsError` | Кириллица в адресе |
| `validate_user_email_InvalidFormat_ReturnsError` | Строка без @ |
| `validate_user_email_TooLong_ReturnsError` | Email длиннее 254 символов |
| `validate_user_email_Valid_ReturnsNull` | Корректный email |
| `validate_user_phone_Empty_ReturnsNull` | Пустой телефон (необязательное поле на сервере) |
| `validate_user_phone_InvalidOperator_ReturnsError` | Неверный код оператора |
| `validate_user_phone_ValidShort_ReturnsNormalized` | 9 цифр без кода страны |
| `validate_user_phone_ValidFull_ReturnsNormalized` | Полный номер +375 |
| `validate_user_address_TooFewParts_ReturnsError` | Менее трёх частей адреса |
| `validate_user_address_NoHouseNumber_ReturnsError` | Дом без цифры |
| `validate_user_address_Valid_ReturnsNormalized` | Корректный адрес и нормализация |

## Описание юнит-тестов (JavaScript)

| Тест | Назначение |
|------|------------|
| `emailError_Empty_ReturnsError` | Пустой email |
| `emailError_InvalidCyrillic_ReturnsError` | Кириллица |
| `emailError_Valid_ReturnsNull` | Валидный email |
| `phoneError_EmptyRequired_ReturnsError` | Пустой телефон (обязательный) |
| `phoneError_EmptyOptional_ReturnsNull` | Пустой телефон (необязательный) |
| `phoneError_InvalidOperator_ReturnsError` | Код оператора 20 |
| `phoneError_Valid_ReturnsNull` | Корректный номер |
| `normalizePhone_FormatsToE164` | Нормализация в +375… |
| `addressError_TooFewParts_ReturnsError` | Неполный адрес |
| `addressError_Valid_ReturnsNull` | Корректный адрес |
| `normalizeAddress_TrimsToThreeParts` | Обрезка лишних частей |

Такой подход к тестированию обеспечивает детальное покрытие критичных бизнес-правил и позволяет своевременно выявлять расхождения между клиентской и серверной логикой. Регулярное выполнение юнит-тестов способствует повышению качества и устойчивости программного обеспечения.
